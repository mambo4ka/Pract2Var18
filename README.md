# Инструмент сбора и визуализации графа зависимостей

## 1. Назначение проекта

Проект представляет собой CLI-приложение для сбора сведений о зависимостях
пакетов. Реализация соответствует первым двум этапам практической работы,
вариант 18.

На первом этапе реализованы загрузка YAML-конфигурации, проверка параметров
и вывод настроек.

На втором этапе добавлен сбор **прямых зависимостей NuGet-пакета**:
- приложение обращается к источнику NuGet V3;
- получает список версий пакета и выбирает последнюю стабильную версию;
- загружает архив `.nupkg`;
- читает файл `.nuspec` внутри архива;
- извлекает прямые зависимости и целевые платформы;
- выводит сведения о пакете и все найденные прямые зависимости.

Для получения данных о пакетах используются стандартные модули Python.
Сторонние менеджеры пакетов и библиотеки для извлечения зависимостей
не применяются. PyYAML используется только для чтения конфигурации YAML.

## 2. Параметры конфигурации

| Параметр | Назначение |
|---|---|
| `package_name` | Идентификатор NuGet-пакета |
| `repo_url_or_path` | URL индекса NuGet V3 или путь к тестовому JSON-файлу |
| `test_mode` | `true` — читать локальный тестовый файл; `false` — обращаться к NuGet |
| `output_filename` | Имя будущего файла изображения графа; используется на следующих этапах |
| `max_depth` | Максимальная глубина анализа; используется на следующих этапах |

В обычном режиме `repo_url_or_path` должен указывать на индекс NuGet V3.
Для NuGet.org используется адрес:

`https://api.nuget.org/v3/index.json`

Если версия пакета отдельно не задана, приложение выбирает последнюю
стабильную версию, опубликованную в источнике.

## 3. Запуск

Установите зависимости проекта:

```bash
pip install -r requirements.txt
```

Запуск обычного режима:

```bash
python src/main.py --config config.yaml
```

Запуск тестового режима:

```bash
python src/main.py --config config.test.yaml
```

Также можно использовать `run.bat` (Windows) или `run.sh` (Linux/macOS).

## 4. Тестовый режим

Файл `test_repository.json` имитирует небольшой репозиторий NuGet.
Пример его структуры:

```json
{
  "packages": {
    "Newtonsoft.Json": {
      "version": "13.0.3",
      "dependencies": [
        {
          "id": "System.Runtime.Serialization.Formatters",
          "version": "[4.3.0, )",
          "target_framework": ".NETStandard2.0"
        }
      ]
    }
  }
}
```

Чтобы проверить тестовый режим, в `config.test.yaml` указаны
`test_mode: true` и путь `test_repository.json`.
Тестовый режим не требует подключения к интернету.

## 5. Структура исходного кода

- `src/main.py` — точка входа, чтение конфигурации и запуск сбора данных.
- `src/config.py` — чтение YAML, проверка параметров и вывод конфигурации.
- `src/nuget.py` — обращение к NuGet V3, загрузка `.nupkg`, разбор `.nuspec`,
  чтение локального тестового репозитория и вывод зависимостей.
- `tests/test_config.py` — тесты проверки конфигурации.
- `tests/test_nuget.py` — тесты выбора версии, извлечения зависимостей
  и тестового режима.

## 6. Проверка

Запуск всех автоматических тестов:

```bash
pytest -q
```

## 7. Ограничения текущего этапа

На втором этапе собираются только прямые зависимости указанного пакета.
Рекурсивный обход зависимостей, построение графа и сохранение изображения
относятся к последующим этапам практической работы.
